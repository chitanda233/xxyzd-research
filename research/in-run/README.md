# 局内核心玩法反拆

> 目标：输出策划可读的“单局运行模型”。配置表、IL2CPP 结构和 ARM64 反编译只作为证据，不把字段本身当报告主体。

## 当前已经闭合的主循环

第一章并不是连续 Survival，而是一条被明确编排的 15 波 Build 时间轴：

**进入关卡 → 按刷新脚本生成敌人 → 击杀并掉落经验 → 波末主动收拢剩余经验 → 处理本波升级选择 → 下一波继续加压 → W10 精英硬门槛 → W15 Boss 硬门槛 → 结算。**

第一章更准确的节奏不是旧版所写的“4+1 / 4+1 / 4+1 三个同构硬节点”，而是：

- W1～W4：快速建立操作与基础 Build；
- W5：第一次高密度脚本峰值，但 **不是** 精英/Boss 击杀锁；
- W6～W9：引入更多怪型组合、随机刷新与攻击压力；
- W10：第一次真正的精英击杀硬门槛；
- W11～W14：第三阶段继续提高混合度与耐久压力；
- W15：最终 Boss 击杀硬门槛。

第一章 Boss 刷新脚本起点约为 345 秒，因此可以把它理解成约 5 分 45 秒的“战斗时间轴”；三选一、波间 UI、精英/Boss 等待会让真实墙钟时间更长。

## 经验曲线与波次是同一条设计曲线

第一章每波的经验预算为：

`200, 550, 600, 600, 700, 800, 800, 950, 1000, 1100, 1200, 1200, 1400, 1700, 2000`

它们的逐波累计值：

`200, 750, 1350, 1950, 2650, 3450, 4250, 5200, 6200, 7300, 8500, 9700, 11100, 12800, 14800`

与 `Exp_exp.waveExp` 前 15 个等级阈值 **逐项完全一致**。因此第一章的基准成长节奏可以明确理解为：

**完整吃完一波经验 ≈ 推进一个等级 ≈ 获得一次局内 Build 决策。**

native 的 `WaterfallBattleManager.InitNewWaveData` 进一步证明 `WaveAllExp` 是一波的总经验预算。系统会统计本波用于经验分配的权重，再计算近似：

```
_perExp = max(1, WaveAllExp / _expCount)
```

具体怪物再依据自身经验权重分走这份预算。这样策划可以改变怪物数量、怪型和强弱，却不让升级频率跟着失控。

## 升级是波末节奏节点，不是任意时刻打断

第一章 `WaitUpLevel=1`。Waterfall 的波末流程会先检查场上是否还有经验/装备掉落；如果经验仍在地上，会调用 `DropMgr.AbsorbAll` 主动吸收。经验动画处理完成且确认可升级后，再根据 `_needUpLevelCount` 进入 `QueueSelectSkill`。

因此第一章更接近：

**打一波 → 收掉落 → 结算经验 → 选一次 Build → 进入下一波。**

代码支持一波积压多次升级，但第一章基础经验预算显然按“一波约一升”校准。这使升级选择本身成为关卡节奏的标点，而不是随机插进战斗流程的暂停框。

## 三选一不是一个静态等概率池

当前已确认的候选生成链至少包含：

**可学习条件过滤 → 按池/SkillType 分组 → 动态权重 → 已学/待学/一星入口分流 → 父技能对子分支二次随机 → Need/Reject/Flag 过滤 → 去重 → 最终候选。**

`HeroComponentRandomSkill` 会按 `SkillType` 统计已学习数量，并通过 `Skill_SkillTypeWeight` 动态修改权重。标准 Type 1 的参数为：

- 每学 1 个：`+50%`
- 最大：`+500%`

底层 `WeightRandomData.PracticalWeight` 已确认公式为：

```
PracticalWeight = BaseWeight × (1 + DeltaWeightPercent)
```

因此 Type 1 的基础权重会从 1.0x → 1.5x → 2.0x → 2.5x……最高 6.0x。这个力度足以明显减少“连续很多次都抽不到武器成长项”的坏随机尾部。

但要特别纠正旧推测：**这套 +50% 是按 SkillType 大类，不是按具体武器家族。** 当前证据不支持“选了冰刃弹以后冰刃弹自己就 +50%”；更准确的是“随着武器类投入增加，武器类合法候选整体被提高相对权重”。

## Build 是“主武器 + 分支 + 模块 + 突破”

局内可见结构目前可归成四层：

- 11 个武器首层入口；
- 7 个通用模块；
- 57 个武器分支强化；
- 111 个深层强化 + 22 个突破/高阶节点。

以速射机炮为例，它不是获得后只做线性升星。主线节点会继续挂接 104 系列的武器分支，例如纯攻击强化，或者“增加正向弹道但牺牲攻击”的取舍型改造。到特定武器节点后，还会要求一个配套模块来解锁 105 系列突破。

例如：

- 速射机炮 10000103 + 暴击模块 11000701 → 10500101 突破；
- 灼热射线 10001703 + 暴击模块 11000701 → 10501701；
- 冰刃弹 10000603 + “缩小！”模块 11001101 → 10500601。

所以这里确实存在类似“主武器 + 配套被动 → 进化/突破”的 Build 结构，而且一个模块通常能服务一到两条武器路线，避免早期选择过快把玩家锁死。

## W5 / W10 / W15 是三个不同职责的 Build 检查点

W5 前玩家大约经历 4～5 次成长选择。它通过刷新脚本密度突然增大来做第一次压力测试，但不锁住关卡推进，因此更像“告诉玩家 Build 开始需要工作”。

W10 前约有 9～10 次成长决策，并出现真正的精英击杀门槛。这里开始检查的不只是走位，而是玩家有没有把一条主要输出链推进起来。

W15 前约有 14～15 次成长决策，最终 Boss 340002 的基础 HP 为 40000，波次 HP 倍率进一步跳高到 11，并且必须击杀才能结束。这是整局最明确的 Build 验收。
