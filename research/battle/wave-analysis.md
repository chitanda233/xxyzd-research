# 第一章 15 波单局节奏还原

> 客户端版本：约 1.0.16 / versionCode 40  
> 目标：把第一章 78 条刷怪指令压缩成策划可读的 15 波节奏，并把“时间推进、击杀门槛、经验升级、波末三选一”串成一个完整循环。

## 核心结论

第一章不是“第 5/10/15 波都是同性质硬节点”，而是明显的三段式结构：

**1～4 波铺垫 → 第 5 波第一次事件高潮（软节点） → 6～9 波继续抬压 → 第 10 波第一次真正硬门槛 → 11～14 波终盘抬压 → 第 15 波最终 Boss 硬门槛。**

第 5 波虽然有额外特殊 UI 类型，但并不要求关键敌人死亡后才能继续；第 10、15 波则明确要求精英/Boss 击杀。因此第 5 波更接近“节奏高潮/事件节点”，第 10、15 波才是真正改变推进条件的硬节点。

第一章的经验曲线也已经完全对齐。15 波经验依次为：

**200、550、600、600、700、800、800、950、1000、1100、1200、1200、1400、1700、2000。**

累计后正好得到：

**200、750、1350、1950、2650、3450、4250、5200、6200、7300、8500、9700、11100、12800、14800。**

这与 `Exp_exp.waveExp` 的 1～15 级累计阈值逐项一致。也就是说，第一章不是“大概一波升一级”，而是数值上明确按照 **“完整打一波 = 恰好跨过下一等级阈值”** 来配置的。

## 怪物层级

为了方便读节奏，下文把第一章主要实体按战斗层级归纳为：

- **杂兵 330006**：Type 2，HP 150，Attack 75，不显示独立血条，单体经验 12。
- **轻型普通怪 320017 / 320021 / 320030**：Type 2，HP 800，单体经验 65。
- **中型普通怪 320019 / 320022**：Type 2，HP 1100～1200，单体经验 65。
- **重型普通怪 320005 / 320035**：Type 2，HP 2350，单体经验 130。
- **第 10 波精英 310008**：Type 201，HP 7000，单体经验 130，掉落类型 3；它在第 10 波开场唯一出现，并与硬门槛配置对应。
- **第 15 波 Boss 340002**：Type 3，HP 40000，单体经验 975，掉落类型 4；最终波唯一核心敌人。

因此第 5 波出现的 320005 虽然血量明显更高，但它仍属于 Type 2，不应与第 10 波的 310008 精英视为同一级别节点。

## 随机刷怪数量的 native 证明

`WaterfallBattleManager.CreateRandomMonster`（RVA 0x65CFF58）不是把随机池候选数组整组生成，而是先取得任务的随机生成数量，再按该数量进入循环。循环中每次只写入一条 `MonsterCreateData`，循环计数逐次 +1；结束时再把 `CreateMonsterCount` 增加同一生成数量。该函数同时受到全局最大生成数 600 的保护。

因此在第一章这批数据中可以把 `numberRandom=N` 直接理解成“本条随机指令实际生成 N 个实体”。由于所用随机池的候选最终都为 330006，所以第 8、10、11、12 波的总怪物数量已经可以精确计算，不再是估算。

## 三个关键节点并不等价

第 5 波、10 波、15 波都带特殊表现，但逻辑性质不同。第 5 波的起始特殊 UI 为 `[1,5]`，但 `StopByEliteOrBossKilled=0`；第 10 波同样是 `[1,5]`，却开启了击杀门槛；第 15 波起始 UI 为 `[1,2]`，并开启击杀门槛。换句话说，特殊 UI 只是“表现节点”，是否成为真正的硬门槛由另外一套推进条件决定。

这让第一章的节奏更像：

**4 波教学铺垫 → 软高潮 → 4 波成长验证 → 精英硬检验 → 4 波终盘成长 → Boss 总检验。**

其中第 9 波和第 13 波这种“数量少、留白多”的波次很重要，它们不是内容不足，而是承担了呼吸和切段作用。

## 波内掉经验，波末统一处理升级

`WaterfallBattleManager.OnProgressFinish` 已经把波末升级链路坐实。流程会先检查场上是否还有经验掉落；如果经验吸收动画仍在运行，会调用 `AbsorbAll`；随后检查经验动画是否空闲以及当前经验是否允许升级，满足条件后才进入 `QueueSelectSkill`。

因此实际结构不是：

**杀怪 → 刚跨阈值 → 立刻弹三选一**

而是：

**杀怪产出经验 → 波内继续战斗/吸收 → 波末收拢剩余经验 → 确认升级 → 进入三选一 → 处理完选择后才继续波末流程/下一波。**

这与第一章 `WaitUpLevel=1` 的配置意义一致：经验来源仍然是怪物掉落，但升级选择被有意延后到波末，避免战斗中途频繁打断。

## 一波跨多级时如何处理

这部分已经可以写成近似伪代码：

```text
每触发一次待升级：
    _needUpLevelCount += 1

进入波末三选一：
    state 0 -> 1
进入选择界面：
    state 1 -> 2

玩家完成一次选择：
    state 2 -> 3
    _needUpLevelCount -= 1
    curWaveUpLevelCount += 1

退出选择后：
    如果仍在波末升级流程：
        state 3 -> 0
        检查特殊技能解锁
        恢复波末升级流程
        如果仍然满足升级条件，再次 QueueSelectSkill
```

native 证据对应关系：

- `AddUpLevel`：字段 `0x1cc` 直接 +1。
- `DelUpLevel`：字段 `0x1cc` -1，同时字段 `0x1c8` +1。
- `ShouldApplyLevelOnSelectSkillEnter`：状态 1→2。
- `MarkWaveEndSelectSkillFinished`：状态 2→3，并调用 `DelUpLevel`。
- `TryResumeWaveEndUpLevelProgress`：只有在 WaveEnd、当前确实是升级 UI、没有经验吸收阻塞、且允许继续升级时才恢复。
- `TryContinueWaveEndUpLevelAfterSelection`：状态 3 清零后继续后续升级/特殊技能流程。
- `QueueSelectSkill`：波末状态为 0 时先标记为 1，然后切入选择状态。

因此“一波一次跨多个等级”时，系统会把多个升级作为待处理计数串行消费，而不是只弹一次三选一或在战斗中同时弹多个 UI。

## 波末成长的策划意义

第一章真正的核心循环可以写成：

**进入波次 → 10～30 秒战斗 → 获得恰好一档等级经验 → 波末暂停 → 三选一塑造 Build → 下一波立即验证刚才的选择。**

5、10、15 波再在这个基础节拍上叠加节点变化：

- 第 5 波：延长窗口 + 特殊表现，第一次让玩家感知“章节正在推进”。
- 第 10 波：精英硬门槛，第一次用敌人死亡而不是时间来决定是否继续。
- 第 15 波：最终 Boss，把局内成长全部集中验证。

这也是后续《局内核心循环反拆》正文最值得保留的结论：**战斗和 Build 不是两套独立系统，而是以“一波一次成长选择”的粒度交替咬合。**
