1. 从策划视角看外围循环

从配置聚类看，局外系统可以先按这条循环理解：战斗产出 → 角色/武器/收藏等能力成长 → 更高强度关卡与模式 → 宝箱/活动/竞技/公会提供额外资源 → 商店和资源兑换形成消耗与补充。这是用于组织研究的产品结构，不等同于已经验证的线上玩家路径。

① 战斗章节、Tower、Survival、Boss 等
② 获得资源掉落、结算、宝箱与活动奖励
③ 能力成长武器升星、收藏、角色/飞行员等
④ 解锁挑战更高章节、竞技、多人和 Boss
⑤ 长线目标公会、赛季、活动、图鉴/收藏
⑥ 资源消耗商店、抽取、兑换、刷新与购买

2. 角色、武器与收藏成长

系统索引把 54 张可读表归入“角色装备与养成”。这部分已经能看到明确的“属性成长 + 技能能力解锁”结构，而不是单纯堆数值。

证据静态字段示例策划层含义
AirplaneGun_Star武器 ID、Star、升星成本、AttrOnStarUp、FeatureInitSkill、FeatureOnStarUp武器升星同时承担属性成长和技能/特性解锁。第一条记录能看到物伤、暴击加成和技能 ID 引用。
Collection_TreasureStartreasureId、star、基础 Attack/HP、升星材料、等级限制收藏/宝物提供另一条长期属性成长线，并带独立材料消耗。
Pilot_PilotAnim 等 Pilot 表PilotID、RoleID、动画等飞行员是独立数据域；当前仅凭动画表不能判断其完整战斗加成，需要继续看其他 Pilot 配置。

后续值得专门做一页“战力来源拆分”：把每一种成长系统最终写入哪些属性、挂哪些 Skill ID、需要哪些材料，统一映射到战斗端。这样才能判断产品真正的长期养成深度和数值复杂度。

3. 掉落、抽取与宝箱

奖励侧至少分成三层：战斗掉落、抽取概率、宝箱规则。Item_drop 保存大批 reward 组合；DrawBox_DrawBoxRateInfo 直接列出物品、数量与概率/权重数值；DrawBox_InventoryDrawCredits 又给不同品质对应 Credits。它们说明奖励系统并不是一个简单“开箱表”，而是有物品池、品质/积分等多个维度。

Shop_LootBox 还出现 FreeCD、钥匙 ID、单抽、十抽、日限制等字段。例如前两条静态记录分别带不同 FreeCD 和 Key_ID。网页暂时只把它确认成“具备免费周期、钥匙和单/十抽成本结构”，不把 FreeCD 的单位擅自解释成小时或天。

4. 商店与资源交换

Shop_Shop 的 note 已经给出很有用的策划语义：第一条是“钻石兑换金币商店”，第二条是“钻石兑换体力商店（递增购买）”。因此至少可以确认商店层承担硬通货向基础资源/体力的转换，而不仅是直接售卖装备。

5. 公会系统

公会/竞技/多人被系统索引归为最大的配置簇之一，共 62 张可读表。单看 Guild_guildStyle 已能确认公会图标样式存在独立配置；Guild_guildcontribute 则出现贡献次数、CostItem 和 guildItems，说明公会至少有“贡献行为 → 公会相关资源”的配置结构。代码侧另有 GuildBossBattleManager，把公会系统直接连接回战斗端。

但这里不应该先写成“每日捐献 N 次”“公会 Boss 每周刷新”等具体运营规则，因为这些需要把全部 Guild 表和服务端时间控制一起对上。

6. 竞技、多人与 Boss

CrossArena_CrossArenaSeason 的静态记录已经非常明确：一个 Season 配置为 Days=7，开放时间 00:00:00 到 23:50:00，使用独立 TicketId，每日恢复 5 张票，并引用 missionId、票券商店和商品。这个表足以说明跨服/跨区竞技在配置层具备“赛季周期 + 门票体力 + 专属商店”的产品结构。

7. 活动、任务与解锁

活动任务与解锁类共有 52 张可读表，而且形式并不单一。Calendar_CalendarFig 的描述字段直接出现“冲刺活动循环的开启时间（开服+N天）”和活动目标参数，说明至少一部分活动采用开服天数和轮次目标驱动。另有 EventBigA_MineRandomRewards、EventDiving_DiveSmallGrid 等不同结构，显示活动层可能包含矿区随机奖励、网格探索等专用小玩法。

这类表尤其需要遵守“静态存在 ≠ 当前启用”：活动资源最容易在客户端长期保留历史版本或未来内容，所以网页只把它们列作活动机制储备和研究入口。

8. 对产品结构的分层判断

层级系统主要目的与核心战斗的连接
核心玩法层章节、刷怪、伤害、随机技能单局体验与构筑决策直接
战力成长层武器、角色/飞行员、收藏/宝物永久成长与构筑差异属性、Skill ID、能力特性
资源层掉落、宝箱、抽取、商店形成产出/消耗循环提供成长材料和资源
长线目标层竞技、多人、Boss、公会重复挑战、竞争与社交目标复用或变体化战斗框架
运营层Calendar、Event、任务、解锁阶段目标、活动节奏和额外奖励通常通过任务条件与奖励反向驱动战斗

9. 证据边界与下一步

当前可以放心使用：表的存在、字段值、已核对的读取顺序、明确的代码类/方法入口，以及配置之间显式 ID 引用。

仍不能直接认定：线上是否开放、服务端开关、活动当前周期、付费价格的真实货币映射、时间字段的业务单位、各系统入口的解锁等级，以及没有被直接调用证据支撑的旧表。

下一轮最有价值的是建立“资源经济图”：把金币、钻石、体力、钥匙、竞技票、公会资源、武器/宝物材料等 Item ID 反查到所有产出与消耗表，最终得到完整经济循环和商业化结构。
