1. 一局游戏的主循环

当前静态证据最支持的闭环是：选择章节/模式 → 加载地图与波次 → 敌人持续刷新 → 战机与僚机执行战斗 → 到达成长节点后从当前有效池里抽取升级项 → 构筑逐步分支/强化 → 完成后获得战斗掉落和关卡奖励 → 回到局外继续战机、武器、僚机、收藏等培养。

① 进入关卡Chapter / Mission / map / wave
② 刷新敌人波次与怪物创建器
③ 战斗结算实体、Buff、受击、技能效果
④ 升级选词条四层 SkillGroup + 加权随机
⑤ 构筑继续前置、分支、后续、高阶节点
⑥ 结算回局外掉落、奖励、永久培养
仍需运行态确认：具体经验条怎么增长、多久弹一次升级、一次出现几个候选、重抽/刷新是否存在，以及 Boss 波的精确切换时机，目前不能只靠静态表下结论。

2. 章节容器与 15 波结构

Chapter_MainChapter 第一条记录已经把章节与战斗参数直接绑在一起：waveNum=15、waveId=100100、地图样式、预览怪物、推荐技能、宝箱类型、首通奖励与完成奖励同时存在。也就是说章节不是只有标题/关卡号，它是把“战斗内容 + 构筑提示 + 奖励”封装起来的一层容器。

层级证据职责

3. 战斗执行：实体 + 技能 + Buff

代码入口 CharacterComponentOnHit、CharacterComponentBuff 与 EntityMonster 支持典型的数据驱动结构：实体配置决定“是谁”，技能/武器/环形效果等配置决定“会什么”，Component 层处理运行时受击、状态和伤害。怪物图鉴表也把 characterId 与 SkillId 直接关联。

Skillss_Ring 里还能看到 RingSlowBullet、RingAddBuffContinue、RingDamageContinue、RingCombine 等效果类名及半径、Buff、Damage、Interval、阵营、目标类型。这说明局内构筑中的一部分效果会真正创建范围/持续逻辑，而不只是给面板加百分比。

4. 真正的局内升级池

之前把 1,184 条 Skill_Main 当成“技能全集”会严重高估玩家实际可选内容。更正确的入口是四张 SkillGroup 表：

池行数作用ID 形态
SurvivorGroup18基础武器与通用强化入口100… / 110…
BranchSurvivorGroup57武器分支强化104…
UpgradeSurvivorGroup111战斗中继续出现的后续升级101…
UpgradeSkillGroup22独立高阶升级池105…

基础池 18 条里可以直接从 notes 确认 11 个武器入口：主武器、酸液弹、电弧枪、霰弹枪、冰刃弹、高爆导弹、黑洞、星空剑、激光炮、旋转锯盘、灼热射线；另有生命、攻击、子弹变大/范围、减冷却、暴击、飞机缩小、血豆掉率/回血等通用强化。

局内升级词条页 会实时把这四张池里的 GetID 与 Skill_Main 反查，展示名称、说明、前置、互斥、后续节点，而不是把整张 Skill_Main 平铺给玩家。

5. 抽取权重随情境变化

基础池和后续升级池都有默认 Weight，并存在 Weight_1 … Weight_10 与 WeightForNewplayer。这直接证明候选项不是永远固定等概率。例如基础“主武器-1”默认权重 100，在前三组情境变成 300 / 250 / 180；“冰刃弹-1”也有同样的前期提升；“旋转锯盘-1”在前三组是 50，却在另一组升到 200。

基础池还存在一条“子弹变大，范围提升-1”，其默认、新手和各情境权重全部为 0。这个案例非常重要：配置存在 ≠ 默认可抽到。后续必须结合条件代码确认它何时会被激活。

此外 Skill_SkillTypeWeight 出现 AddWeightPerSkill=50、AddWeightMax=500。这说明系统还存在类型级动态权重参数，但“是否属于防脸黑/保底”仍需继续追 WeightRandom 的调用逻辑。

6. 局外培养如何注入一局

局内构筑并不是从零开始。武器 的 AirplaneGun_Star 会通过 FeatureInitSkill 与 FeatureOnStarUp 引用技能 ID；战机 Role 本体也有 SuperSkill 和 FeatureSkills；僚机 在 1/2/4/7/10 星节点解锁自己的 SkillDetail。于是完整战斗 Build 更接近：

局外战机/武器/僚机预装能力 + 本局抽到的基础武器/通用强化 + 分支/后续/高阶升级 = 最终一局构筑。

这也是为什么网站把“武器培养”和“局内升级词条”拆成两个页面：前者决定进入战斗前有什么，后者研究进入战斗后还能选什么。

7. 掉落与结算

MainDropManager、DropMgr、Item_drop 支持战斗过程掉落；章节配置又有首通和完成奖励，因此至少存在“局内掉落”和“关卡结算奖励”两层。它们共同把资源送回局外的战机、武器、僚机、收藏等成长线。

8. 同一骨架上的模式变体

主线 Chapter

15 波等章节结构最完整，直接挂推荐技能与奖励。

Room / Tower

独立 Mission 表改变房间规则、倍率和刷新参数。

Waterfall / Survival

独立 BattleManager 表明存在持续生存型战斗管理分支。

多人 / Boss

WaterfallMulti、GuildBoss、WorldBoss 各有专门 BattleManager。

9. 下一步最值得追的逻辑

  1. 升级事件到底如何触发，以及一次生成几个候选。
  2. 四层池的进入/退出条件，尤其 104 分支与 105 高阶节点。
  3. PreSkillIds / NeedSkills / RejectSkills / UpgradeSkillId / NextSkill 的筛选先后顺序。
  4. Weight_1…10 各自对应什么战机、武器、模式或构筑状态。
  5. 局外 FeatureSkill 与局内抽取池发生重复时，系统是升级、替换、覆盖还是过滤。
