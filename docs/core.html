局内核心循环反拆

1. 一局到底怎么跑

第一章当前最完整的运行模型是：进入关卡 → 按脚本批次刷怪 → 击杀产生经验掉落 → 波末主动吸收遗漏经验 → 结算本波升级 → 从当前合法候选里做 Build 选择 → 下一波继续加压 → W10 精英硬门槛 → W15 Boss 硬门槛 → 结算回局外。

① 进入关卡装入本章 15 波与推荐 Build
② 刷怪推进位置组、定时批次、随机组混合
③ 击杀掉落经验按本波总预算向怪物分配
④ 波末收束吸收残留经验，统一处理升级
⑤ Build 选择品质分池 + 合法性过滤 + 新手保护
⑥ 节点验收W10 精英、W15 Boss 检查输出成型

这和典型“无限时间轴上不断刷怪，经验条一满就随时弹升级”的 Survivor 结构不同。《小小远征队》把“刷怪段”和“成长决策”绑得更紧：经验总量先由波次定义，波末再把遗漏掉落吸回来，最后统一进入选技能流程。这样一来，关卡策划能够知道玩家在进入下一波之前大致已经做过多少次成长决策。

2. 第一章 15 波：不是三个相同的 4+1

旧版分析曾把第 5、10、15 波都视为相同的“精英/Boss 强制击杀节点”，原因是读取了通用 Section 数据。重新沿着第一章实际引用的 waveId=100100 追到 ChapterWave_Waves 后可以确认：W5 并没有开启击杀锁，真正的硬门槛只有 W10 与 W15。因此三个阶段虽然都大约五波，但高潮职责并不相同。

3. 为什么可以说“一波约一升”

第一章的每波经验不是随怪物数量自然漂出来的，而是关卡层先给出一份明确的总预算。更关键的是，这 15 份预算的逐波累计值和玩家前 15 个升级阈值逐项完全相等。

节点本波经验累计波经验对应升级阈值含义
W1200200200第一波完整经验正好跨过第一个阈值
W570026502650第一次压力峰前后约已有 5 次成长
W10110073007300精英门槛前约已有 10 次成长
W1520001480014800经验预算仍覆盖阈值，但没有普通波末 UI，不能机械计为第 15 次常规三选一

native 实现解释了为什么怪物数量变化却不会破坏这条成长曲线。新波开始时，WaterfallBattleManager 会先统计本波的经验分配权重，再把 WaveAllExp 除以总权重得到基础份额；具体怪物再按自身 expWeight 分走对应份数。也就是说，重怪可以拿更多经验，密集小怪可以拆成更多份，但整波最终仍然围绕同一个经验总预算。

波末还会检查场上是否留有经验掉落；如果还有，会主动执行 AbsorbAll，等待经验动画进入可升级状态，再把待处理升级送入选技能队列。策划结果非常清楚：经验不是只负责奖励击杀，它还承担“把玩家准时送到下一次 Build 决策”的节奏控制。

4. 三选一：先定整组品质，再从合法池里抽具体技能

普通主线一次升级的候选数由 MainChapterRandomSkillCount = 3 控制。当前 native 表明，它不是“三张牌分别独立抽品质”，而是先用 Const.RandomSkillWeight = 40 / 40 / 20 / 0 对整组三选一只抽一次起始品质，然后进入该品质对应的 WeightRandom 池里尽量抽满 3 张。只有当前品质的合法候选不够，才轮转到后续品质池补齐。

① 选候选体系普通池，或首轮 Init 池
② 抽整组品质普通主线基础 40 / 40 / 20 / 0
③ 合法性过滤前置、互斥、Flag、最大星级、NeedSkill
④ 池内加权抽取同品质候选按自身 WeightRandom 权重抽
⑤ 分支处理父技能多个子升级时只随机一个合法分支
⑥ 不足再补池无重复补满 3 张后展示

刷新和“品质提升”也是两种不同操作。普通刷新会复用上一轮保存的品质索引，因此更接近“在同一品质框架里换牌”；qualityUp 则会把本轮整组三选一的起始品质直接上移一档，再从新品质池取候选。角色的高品质技能相关属性还会在进入品质骰之前修改第 2、3 档的临时权重。

候选本身会随 Build 状态变化。已学习技能可以继续走升级链；满足前置的新技能会进入候选；达到最大星级的节点会退出普通升级；NeedSkill、SkillFlag、RejectSkill 等继续过滤；一个父技能存在多个子升级时，客户端会先在合法子分支中再随机一个，而不是让所有子分支同时占满三选一。因此即使不依赖任何“同类型增权”，玩家持续选择某条路线后，后续合法候选池本身也会自然改变。

客户端还准备了独立的 _initRandoms 与普通 DefaultRandoms。当 BattleData.InitSkillGroupCount 大于 0 时会先使用 Init 池并消费一次计数，配置 UseInitSkillGroupCout = 1 与“一次首轮定制池”的设计目标吻合；但当前静态证据还缺初始化阶段把这个常量写入运行时计数的最后一个调用点，所以这里把它写成存在且目标为一次的首轮池机制，不伪装成已闭合的调用链。

真正已经生效的概率扶正：新玩家保护会对配置中的核心技能执行一次性的 BoostWeightByPercent，当前配置为 +10%；本轮抽完后立刻用 RevertWeightBoost 撤销。也就是说，游戏确实会为了前期体验临时倾斜某些技能，但不会永久污染基础权重。

同 SkillType 动态增权：设计公式存在，但当前 APK fallback 没有落地

Skill_SkillTypeWeight 的设计参数基本都是“每学一个同类型技能计划 +50%，最高 +500%”。GetDeltaWeightPercent 也确实读取同类型已学数量并计算 min(learnedCount × 50%, 500%)，新增/移除技能时还会调用 AdjustWeightsForSkillGroup。

但关键反证是：当前 1.0.16 APK 的 AdjustWeightsForSkillGroup fallback 是空实现。它没有把刚算出的增幅写进任何 WeightRandom，而 HeroComponentRandomSkill 里也找不到对 WeightRandom.UpdateWeightPercent 的直接调用。只有运行时 hotfix 覆盖这个函数时，才可能启用真正的同类动态增权。

因此当前策划报告只能写：客户端设计过“同类越学越容易出”的 +50%/次、+500% 封顶模型，但 APK 基线是否实际启用未证实。普通主线已经确认生效的随机控制，主要来自整组品质抽取、合法候选重构、首轮池结构和新玩家临时扶正，而不是这条尚未落地的长期动态增权。

另外，Exp_exp.randomSkillFactor 不是普通主线三选一的品质权重。普通分支使用的是 Const.RandomSkillWeight，并把 randomSkillFactor 置空；前者只在 Danke / 特殊技能路径中被读取。之前把 [1/2,40,40,20] 解释成普通主线四池权重的结论已经作废。

5. Build 怎么从一张牌长成完整路线

局内真正可见的 Build 不是 1,184 条底层 Skill_Main 的平铺，而是四层结构：11 个武器入口、7 个通用模块、57 个武器分支、以及 111 个深层强化加 22 个突破节点。Skill_Main 更适合作为效果实现与配置附录，不应该直接等同于“玩家有 1,184 个技能可选”。

武器主线

首次获得决定攻击方式，后续通过 NextSkill 推进星级与阶段。

武器分支

主线升级时可挂接归属武器的 104 系分支，形成弹道、伤害、频率与副作用差异。

通用模块

攻击、生命、冷却、暴击、维修等既提供泛用收益，也充当部分武器突破的配方件。

突破 / 深层强化

达到指定武器节点并拥有对应模块后，解锁 105 系突破和更深层的 101 系强化。

以速射机炮为例：首次获得后，主线继续升级；二星以后会挂接自己的 104 系分支，其中既有纯攻击强化，也有“增加正向子弹但降低攻击力”这种带取舍的改造。到 3 星节点后，如果玩家同时拿到暴击模块，就能解锁对应突破。灼热射线也共享暴击模块作为自己的突破组件，而冰刃弹则与“缩小！”模块形成另一条配方关系。

所以一条完整 Build 更接近：主武器 → 主线等级 → 武器专属分支 → 配套通用模块 → 突破 / 深层强化。同一个通用模块可以服务一到两条武器路线，这让早期选择既有方向感，又不会过早把玩家锁死。

6. W5、W10、W15 为什么要做成三种不同节点

节点玩家约已完成的成长决策关卡手段检查内容
W54～5 次刷新任务密度突然放大，不锁推进有没有形成最初的战斗方向；失败成本不能太重
W109～10 次精英 310008 + 必须击杀；击杀后截断未执行刷新主输出链是否已经具有足够单体/持续伤害
W15Boss 前已有 14 个明确的常规波末成长节点Boss 340002 + 更高 HP 倍率 + 必须击杀武器、分支、模块、突破是否真正形成完整 Build

这种编排比“每五波单纯把 HP 再乘一档”更有效。W5 允许玩家在 Build 尚未成熟时体验一次明显峰值，却不通过硬门槛把坏随机直接判死；W10 再开始要求输出成型；W15 才做最终验收。更细的 native 行为还表明，W10/W15 的门槛验收对象是 Type 201 精英或 Type 3 Boss：特殊目标清零后会清除尚未执行的怪物创建计划，而不是要求未来定时批次全部刷完。普通怪在这里更多承担干扰与环境压力，关键目标才是节奏开关。

7. 这些设计为什么这样做

第一层价值是可控节奏。经验预算与等级阈值完全对齐，让策划能够非常稳定地知道“第几波之前玩家大约做过几次选择”，因此怪物压力、精英/Boss 与 Build 成长可以在同一张时间表上调，而不是两个系统各自漂移。

第二层价值是减少 Roguelike 随机的挫败尾部。候选仍然随机，所以每局会有变化；但整组品质分池、前置过滤、父子分支、首轮定制池结构和新玩家一次性权重扶正，会持续把结果拉回“可理解、可继续成长”的区间。客户端还保留了同 SkillType 长期动态增权的设计框架，但当前 APK fallback 没有实际应用，因此不能把它算进已生效的反坏运气机制。

第三层价值是让选择同时具备短期收益和长期路线承诺。拿一个通用模块不仅改变当前数值，还可能成为某把武器未来突破的配方件；拿一把武器也不只是增加一个自动攻击，而是开启后续主线与分支池。这样三选一里的一张牌会同时影响“现在打得更轻松”和“后面能不能完成质变”，决策密度明显高于普通百分比加点。

第四层价值是支撑重复游玩而不完全依赖重运营。相同章节可以因为武器入口、分支取舍、配套模块和突破顺序不同形成不同战斗形态；而动态随机又避免重开后体验完全被坏运气摧毁。至于这些结构具体怎样与付费入口连接，还需要外围经济与商业化单独反拆，当前局内证据不足以直接推导付费结论。

8. 当前已经确认什么，什么还没有

已经确认：第一章 78 条任务压缩后的 15 波刷新结构；W5 是软高潮、W10/W15 为硬门槛；W1～W14 明确走普通波末成长 UI；每波经验预算与前 15 级阈值差逐项对齐；波末会吸收残留经验并按 pending level 串行处理多次三选一；普通主线一次给 3 个候选；先抽一次整组品质再从该品质的 WeightRandom 中无重复取技能；刷新复用品质索引；候选会受已学状态、前置、互斥、最大星级和父子分支影响；新玩家保护会临时给特定技能 +10% 后再撤销；武器节点 + 模块 → 突破的 Build 配方关系。

尚未写死：W15 的 2000 经验是否在实机 Boss 死亡后仍触发特殊成长选择；首轮 Init 池计数与 UseInitSkillGroupCout=1 的初始化最后调用点；同 SkillType +50%/次、+500% 封顶是否由线上 hotfix 真正启用；Danke 路径中 Exp_exp.randomSkillFactor 的四个数具体语义；失败、复活、三星条件和结算奖励如何与局外经济闭环。
